What is different

Built for the person who has to sign the register.

It says what it did not look at

Every scan lists what was examined and what was not, with the reason. No tool can prove code is safe; this one is explicit about its limits.

Catastrophic stays visible

Lowering the severity of a catastrophic scenario needs a written justification and is flagged in the audit trail.

Your environment, your model key

Runs where you run it and calls the model provider you choose, including a European one. Recognised secrets are redacted before any text is sent.

Your code is treated as untrusted

Instructions hidden in code or documentation are handled as data. Our test set includes repositories written to make the scanner report nothing; they do not succeed.

Questions

What people ask first.

Where does our code go?

It stays in the environment where Faultmap runs. Portions are sent to the language-model provider you configure, under your own account and key. Values in environment files and recognised credential patterns are redacted first.

Does this replace our scanner?

No. Scanners find known patterns quickly and cheaply, and you should keep them. Faultmap answers a different question: of everything that could go wrong in this system, what matters most to the business, and why.

Which languages and models?

Code navigation is deepest for Python, Java, C# and TypeScript; other languages are read as text. OpenAI and Mistral models are supported today, with more providers planned.

Does it connect to pull requests and ticketing?

Not yet. These are next, and design partners decide the order.

What does FMEA have to do with it?

Failure Mode and Effects Analysis is the method safety engineers have used for decades to rank what could go wrong by severity, likelihood and detectability. Faultmap applies it to software, continuously, from the code.
